Moving the CMG → R&D → Finance workflow onto Malee systems

Written for management and IT. The prototype proves the flow; production needs Malee's own logins, storage and notifications. Nothing below assumes which systems Malee runs today — please confirm with IT.

1. Feasibility summary สรุปความเป็นไปได้

Feasible, low-to-medium effort. It is a standard request → approval → costing workflow with one shared reference list (material codes). No unusual technology is needed.

Recommended
Option A (Microsoft 365) if Malee already uses Microsoft 365 / Outlook / Teams. Otherwise Option B (Google) or C (custom).
Rough effort (estimate)
~6–10 weeks to go live for one product family (coconut), incl. a pilot.
Team (estimate)
1 business owner (CMG lead) · 1 Power Platform / app developer · part-time IT admin (SSO, permissions) · key users from R&D and Finance-Factory for testing.

Option A — Microsoft 365 (SharePoint / Dataverse + Power Apps + Power Automate)

  • Each table below becomes a SharePoint List (or Dataverse table). Materials list becomes the lookup source for formulation lines.
  • Power Apps form = the CMG template; R&D and Finance screens show only their queue (filtered by status and role).
  • Power Automate: on Submit → create audit row, email/Teams R&D; on "Sent to Finance" → notify Finance; on Approve/Send back → notify CMG/R&D. Use Approvals for sign-off with timestamp.
  • Entra ID groups (CMG, R&D, Finance-Factory, Admin) control who sees and edits what. Attachments stored in a SharePoint document library.

Option B — Google Workspace (AppSheet or Sheets + Apps Script)

  • One Google Sheet with a tab per table (or AppSheet database). AppSheet builds the form, queues and role views with little code.
  • Automations send Gmail and Google Chat messages at each status change; timestamps and user email logged automatically.
  • Google Groups for roles; attachments in a shared Drive folder. Good for speed; Sheets is less suited to very large volumes.

Option C — Custom web app on Malee's server or cloud

  • Postgres database (self-hosted or a managed service such as Supabase) plus an API; the prototype's screens are re-used and connected to it.
  • Row-level security by role; SSO through Entra ID or Google; notifications via email, Teams or LINE webhooks.
  • Most flexible (e.g. complex costing, ERP sync, dashboards) but needs a developer for build and maintenance.

5. ERP tie-in for material codes เชื่อมต่อ ERP

If Malee uses SAP or another ERP (confirm with IT), material codes, descriptions, units and standard costs should be pulled from the ERP material master rather than uploaded by hand — e.g. a scheduled export (daily CSV to SharePoint/Drive) or an API/connector (SAP has connectors for Power Automate; other ERPs typically offer exports or APIs). Benefits: one source of truth, current standard costs, no duplicate codes. The app keeps a read-only copy; R&D can only pick active codes; Finance overrides are logged with a reason. Later, an approved costing could be written back to the ERP if IT wants.

6. Step-by-step migration ขั้นตอนการย้ายระบบ

  1. Export the prototype data — Admin → Data tools → Export all data (JSON). Gives IT a working sample of every record type (mock data).
  2. Create the tables on the chosen platform using the data model below.
  3. Load the full material code list — CSV with columns code, description, category, unit, std_cost_thb, supplier, active (same format as the prototype's import), or connect the ERP feed.
  4. Set role permissions — CMG creates/edits own requests; R&D edits formulations; Finance edits costings; Admin manages materials and users; everyone read-only on audit log.
  5. Build notifications at each status change (Submitted, Sent to Finance, Costing done, Returned).
  6. Pilot one real CMG coconut request end-to-end with named users; compare with the email process; adjust fields.
  7. Go live for coconut products; stop the email route; then add other product lines.

7. Security & data governance ความปลอดภัยและธรรมาภิบาลข้อมูล

  • Keep real data internal. Formulations and costs are confidential: host only on Malee's tenant/servers with company login. The current public GitHub page must stay mock-data only.
  • Access by role — least privilege; Finance cost data hidden from roles that don't need it (e.g. CMG sees approved price, not cost breakdown, if management prefers).
  • Audit trail — append-only log of who did what and when; formulation versions kept, not overwritten.
  • PDPA — the system holds personal data (staff names, customer contact names/emails): collect only what is needed, restrict access, set retention, and follow Malee's PDPA policy.
  • Backups & retention — platform backups; define how long requests and formulations are kept.
